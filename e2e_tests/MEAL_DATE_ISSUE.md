# Проблема: Meal всегда создается на сегодняшнюю дату

## Текущее поведение

При создании meal через `MealElementScreen`:
- ❌ Meal **всегда** создается на **сегодняшнюю дату**
- ❌ Выбранная дата на главном экране (`MainScreen`) **игнорируется**
- ❌ Нет возможности выбрать дату на экране создания meal

## Ожидаемое поведение

1. ✅ Meal должен создаваться на **выбранную дату** из `MainScreen`
2. ✅ Если пользователь выбрал "вчера" на главном экране, meal должен создаться на вчера
3. ✅ Если пользователь выбрал "завтра", meal должен создаться на завтра

## Техническая проблема

### Текущая архитектура:
```
MainScreen (выбрана дата: вчера)
  ↓ FAB клик
SearchScreen
  ↓ Выбор продукта
MealElementScreen (нет информации о дате!)
  ↓ Добавить
Meal создается на СЕГОДНЯ ❌
```

### Проблема:
- `MealElementScreen` не получает информацию о выбранной дате
- Дата не передается через navigation params
- Нет UI элемента для выбора даты

## Дополнительные требования к UI

### Прогноз потребленных калорий

Пользователь должен видеть **прогноз потребленных калорий** при добавлении продукта в прием пищи.

**Текущее состояние:**
- В `MealElementScreen` отображается только текущее количество калорий продукта
- Нет информации о том, сколько калорий будет потреблено после добавления

**Ожидаемое поведение:**
1. При вводе количества продукта показывать:
   - **Текущие калории дня** (из DailySummary на MainScreen)
   - **Прогноз калорий после добавления** (текущие + калории продукта)
   - **Разница** (сколько добавится)

**Пример UI:**
```
MealElementScreen:
  - Header: "Добавление - 31 января"
  - Product: Яблоко
  - Quantity: 150 г
  - Calories: 75 ккал
  
  📊 Прогноз калорий:
  Текущие: 1200 ккал
  После добавления: 1275 ккал (+75 ккал)
  
  - Meal Type Selector
  - Add Button
```

**Реализация:**
- При изменении количества продукта пересчитывать прогноз
- Показывать прогноз в реальном времени
- Можно добавить визуальный индикатор (зеленый/желтый/красный) в зависимости от дневной нормы

## Решения для фронтенда

### Вариант 1: Автоматическая передача даты (РЕКОМЕНДУЕТСЯ)

**Изменения:**
1. При открытии `SearchScreen` через FAB передавать выбранную дату из `MainScreen`
2. При открытии `MealElementScreen` передавать дату из `SearchScreen`
3. Использовать эту дату при создании meal

**Пример кода:**
```typescript
// MainScreen.tsx
const handleAddMeal = () => {
  navigation.navigate('Search', { 
    selectedDate: currentSelectedDate  // Передаем выбранную дату
  });
};

// SearchScreen.tsx
const { selectedDate } = route.params;

const handleProductSelect = (product) => {
  navigation.navigate('MealElement', { 
    product,
    selectedDate  // Передаем дальше
  });
};

// MealElementScreen.tsx
const { selectedDate } = route.params;

const handleAdd = () => {
  createMeal({
    productId: product.id,
    date: selectedDate,  // Используем переданную дату
    mealType: selectedMealType,
    quantity: quantity
  });
};
```

### Вариант 2: DatePicker в MealElementScreen

**Изменения:**
1. Добавить DatePicker в `MealElementScreen`
2. По умолчанию использовать выбранную дату из `MainScreen`
3. Позволить пользователю изменить дату при необходимости

**UI структура:**
```
MealElementScreen:
  - Header: "Добавление - 31 января" (отображает дату)
  - DatePicker: [31 января ▼] (кликабельный, можно изменить)
  - Product Info
  - Nutrients
  - 📊 Прогноз калорий:
     Текущие: 1200 ккал
     После добавления: 1275 ккал (+75 ккал)
  - Meal Type Selector
  - Add Button
```

### Вариант 3: Использовать глобальный state/context

**Изменения:**
1. Создать `DateContext` для хранения выбранной даты
2. `MainScreen` обновляет контекст при изменении даты
3. `MealElementScreen` читает дату из контекста

## Рекомендация

**Вариант 1 (Автоматическая передача)** - самый простой и надежный:
- ✅ Минимальные изменения в коде
- ✅ Соответствует принципу "least surprise" (пользователь ожидает что meal создастся на выбранную дату)
- ✅ Не требует дополнительных UI элементов
- ✅ Работает интуитивно
